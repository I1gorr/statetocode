A diagram is an image. Software needs a graph.

Protocol and interface state machines are drawn as pictures. Someone re-types them as code by hand, which is slow and easy to get wrong.

States

Labels

Start and end

One wrong endpoint means code with wrong behaviour. The goal is not to detect shapes. It is to rebuild the correct graph, and to say when the system is unsure.

YOLO11n finds the parts, but only as boxes

Six classes

statearrowfinal_statearrowheadinitial_markerlabel

A single-stage detector gives a box and a confidence for each object. The nano model is small and fast, and these line drawings need no bigger network. It starts from pretrained weights.

The limitation

A box shows where an arrow is, not where it starts, ends or points.

Boxes of crossing or curved arrows overlap and contain other objects. Connectivity needs the pixels of the stroke itself.

The detector is nearly solved on this data

Source: Ultralytics validator run on dataset_v2 test images with runs/detect/v2/weights/best.pt, image size 640. Precision and recall are measured at the confidence that maximises F1.

That is why the interesting work is the next cards: turning boxes into a correct graph.

First, a clean ink mask, even from a shadowed photo

  1. Estimate backgroundA large morphological closing removes thin lines and keeps paper shading.
  2. Divide it outImage divided by background flattens shadows and gradients.
  3. Otsu thresholdThe ink and paper cut-off is chosen from the histogram.
  4. Remove speckleA small morphological opening cleans up noise.

The distance transform also gives the median pen width, so the tracer adapts to thick and thin lines.

Follow the pen, do not guess the nearest state

A to B and C to D cross at the orange ring. The tracer keeps its heading, so each edge stays whole.

  1. Regions. Remove each state from the mask, so arrows become free strokes.
  2. Ports. A port is where ink touches a thin ring around a state.
  3. Trace. Walk the stroke in 2 px steps. Turning is penalised, and gaps up to 14 px are bridged.
  4. Stop. Entering a state is an edge, returning to its own state is a self-loop, no ink is a free end.

Every arrow is traced from both ends and the traces are cross-checked.

The arrowhead is the evidence for direction

1.0
Width ratio at a plain end of the shaft
2.2+
Width ratio at an arrowhead (the head_ratio threshold)
  • Primary: a detected arrowhead box at the arrow's own end.
  • Fallback: ink cross-section near each end divided by the shaft width. The wider end is the head.
  • Exclusive: each arrowhead belongs to one arrow only.
  • Weak evidence: direction becomes unknown and both readings are shown.

Start and end states, names and labels

Initial state

A free-ended arrow whose head touches a state, or a detected initial-marker box next to it.

Final state

The final_state class, or a double ring found by sampling the radial ink profile at 90 angles.

Reading text

Tesseract on an upscaled crop with outline fragments removed first. Each label goes to the transition whose traced path is nearest.

Label meaning

timeout [retries<3] / retransmit

Parsed into event, guard and action. Words like SYN, ACK or timeout mark a network event. Unknown words stay plain events.

Schema 1.1, validated twice

JSON Schema first, then graph rules:

  • No dangling references or duplicate ids
  • At most one initial state
  • No non-deterministic transitions
  • No transitions out of final states
  • No unreachable states

The editor, validator, code generator and evaluation all read this one file.

Generated code is checked against an independent reference

A. Template generator

A dependency-free StateMachine class. Guards are injected functions. Actions run before the state changes.

B. Reference model

A separate implementation of the same semantics, used as the oracle for what should happen.

A must equal B

The plan fires every transition plus guard-rejection and invalid-event probes. States and errors must match exactly.

InvalidEventErrorGuardRejectedErrorTerminalStateErrorNondeterministicTransitionError
360 of 360 predicted graphs produced code that passed the full plan. Deliberately broken code is caught by mutation tests. Conformance shows the code matches the graph, not that the graph matches the drawing.

Sandboxed execution, and a limited role for Gemini

Sandbox

  • An AST allowlist rejects os, socket, subprocess, open, eval and exec before anything runs
  • Separate isolated interpreter, empty environment, temporary directory
  • Timeout plus CPU, memory, file-size and process limits
  • Audit hook blocks sockets, subprocesses, file writes and ctypes

Defence in depth for a local tool, not a container.

Gemini (optional)

  • Explains the diagram in plain language
  • Suggests corrections that you accept or reject
  • Can write alternative code, which must pass the same checks
  • Replies must match a JSON contract, and invented states are dropped

It never detects arrows, validates the graph or accepts code.

We score the whole graph, not just the boxes

Match by geometry

Predicted states are paired with true states by box overlap of at least 0.5, using the Hungarian algorithm. Never by id, because ids only record detection order.

Strict graph checks

Directed transition F1, endpoint accuracy, initial and final state accuracy, whole-graph exact match.

Text error

Exact match, and character error rate: edit distance divided by the true length. Zero is perfect.

A web editor, and a loop that learns from fixes

Editor

  • Detections shown over the image, next to the rebuilt graph
  • Drag states, add transitions, reverse direction, undo and redo
  • Uncertain items are amber and dashed, and the Issues tab lists them
  • Edits to the JSON are validated before they are accepted
  • The Code tab marks generated code stale after any change

Correction loop

  1. Predict and review the graph
  2. Fix it and click Save correction
  3. Export corrections as YOLO labels
  4. Fine-tune the detector
  5. Measure on held-out corrections that were never trained on

What the numbers do not claim

Synthetic data only

Photos and handwriting are out of distribution. No real corrections have been trained on yet.

Label OCR is the weakest stage

65 percent of labels are read exactly. A misread guard changes behaviour, so review guards.

Hard association cases

Shallow crossings, arrows under text and tiny self-loops. Flagged when detected, not always.

Scope of verification

Only Python is executed and checked. The sandbox is process isolation, not a container.
